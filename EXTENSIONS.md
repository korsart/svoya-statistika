# Дашборды и интеграции

Основа работает без модулей. Расширения живут отдельно от счётчика и не нужны для отправки событий. Это позволяет добавить расходы или данные CRM, не меняя формат браузерных событий и не отправляя ключи в JavaScript.

## Готовый необязательный пример: расходы

1. Скопируйте examples/integrations.example.php в **site-stats-private/integrations.php**, вне публичного сайта.
2. Скопируйте examples/budget.example.json туда же как **budget.json**. Замените вымышленные даты и суммы своими. Не загружайте эти файлы в public_html.
3. Откройте отчёт. Появится вкладка «Расходы»: план на период, фактические расходы и остаток.

Это ручной источник, не подключение рекламного кабинета. Суммы в рублях, один объект на день. budget означает план на этот день, spend фактические расходы на этот день. Не повторяйте месячный бюджет в каждой строке. Период выбирается на дашборде. Если расход выше плана, остаток будет отрицательным. Без записей за период выводятся нули. Ошибка файла не ломает основной счётчик: вкладка показывает, что данные недоступны.

## Как подключить сервис

Контракт в public/site-stats/extensions.php:

```php
interface SiteStatsIntegration {
    public function id(): string;
    public function title(): string;
    public function report(DateTimeImmutable $from, DateTimeImmutable $to): array;
}
```

Новый адаптер реализует этот интерфейс. Его PHP-файл и конфигурация хранятся в приватной папке. integrations.php подключает класс и возвращает массив экземпляров. Интерфейс уже загружен до чтения реестра. До 8 модулей. id уникален, латинскими буквами, цифрами, underscore или дефисом; длина 2–31, начинается с буквы, site зарезервирован. title выводится как текст с HTML-экранированием.

report возвращает строго данные, не произвольный HTML:

```php
return [
  'note' => 'Расходы из подключённого рекламного кабинета. Обновлено 13.10.2026 10:00 МСК.',
  'metrics' => [
    ['label' => 'Расходы', 'value' => 12345.50, 'unit' => 'RUB'],
    ['label' => 'Заявки в CRM', 'value' => 17, 'unit' => 'count'],
  ],
];
```

Допустимые unit: RUB, count, percent. До 8 метрик. Числа конечные, текстовые поля ограничены. Интерфейс оформляет карточки сам. Пример формата выше вымышленный, не результат реального API. Для отдельного графика или таблицы можно расширить версионируемую схему отчёта и renderer, не затрагивая collect.php и tracker.js.

Внешние данные лучше получать по расписанию отдельной задачей хостинга и складывать в приватный кеш. report читает кеш, чтобы открытие страницы не ждало рекламный API. Для сетевого адаптера нужны ограничение времени запроса, проверка TLS, лимитов и ошибок, дата обновления и явное состояние устаревших данных. Токены только в приватной конфигурации или переменных окружения. Ошибки не должны раскрывать токены/адреса API пользователю; исключения отчёта перехватываются с нейтральным сообщением. Автоматический планировщик, OAuth и реальные API-интеграции в 1.0 не реализованы.

## Границы модулей

```
Сайт → tracker.php / tracker.js → collect.php → приватная статистика
                                                   ↓
                                      index.php → дашборд сайта

API / файл → адаптер → приватный кеш → SiteStatsIntegration → дополнительный дашборд
```

Общие части: вход, период, часовой пояс, внешний вид и экранирование. Раздельные части: сбор событий, источники сторонних данных и представление их отчёта. Бюджет и число заявок не означают автоматически корректную цену заявки: сначала нужно согласовать валюту, период, источник, атрибуцию и тип заявки. Нельзя молча делить любые расходы на любые заявки.

Расширения исполняют PHP на сервере владельца и считаются доверенным кодом. Перед установкой чужого адаптера прочитайте его код. Через дашборд нельзя загружать/исполнять произвольные плагины.
