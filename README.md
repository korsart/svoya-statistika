# Своя статистика

Бесплатный открытый счётчик и закрытый дашборд для небольшого сайта. Размещаются на вашем хостинге. Код не отправляет события на серверы TRIKE или Яндекса. Лицензия MIT: можно использовать, менять и внедрять клиентам, сохраняя текст лицензии.

**[Скачать готовый комплект](https://github.com/korsart/svoya-statistika/raw/refs/heads/main/downloads/svoya-statistika-v1.0.0.zip)** · [Инструкция](https://github.com/korsart/svoya-statistika/blob/main/README.md#установка) · [Расширения](EXTENSIONS.md)

**Начните с start.html.** Откройте его в браузере после распаковки архива. Демо в demo.html содержит только вымышленные цифры. Промпт для установки с нейросетью в AI-PROMPT.md. Текст для контента в POST.md.

## Что умеет

- Сессии вкладок, просмотры разрешённых страниц, источники и категории устройств.
- Telegram, WhatsApp, телефон, почта, целевая кнопка и явно подтверждённая заявка.
- Периоды 7, 30 и 90 дней, график, разбивка по источникам и страницам, экспорт CSV.
- Сбор после разрешения на аналитику, отказ и отзыв через API.

Сессия: активность в одной вкладке с перерывом между событиями до 30 минут. Разные вкладки могут считаться отдельно. Это не уникальные люди. Источник закрепляется при начале сессии; другой UTM внутри неё его не меняет. Вкладка без событий больше 30 минут при следующем действии начинает новую сессию. Только просмотры, соответствующие настройкам страницы, попадут в отчёт.

UTM: счётчик читает только utm_source и переводит его в фиксированную категорию. Поддерживаются telegram/tg, youtube/yt, vk/vkontakte, instagram/ig, threads, yandex, google. Остальные значения дают «Другие UTM». Полные UTM, кампании и содержимое меток не сохраняются. Без UTM определяется категория по referrer. Неизвестный источник объединён с прямыми переходами.

## Кому подходит

Небольшой сайт на обычном PHP-хостинге. Один сайт на одну установку, до 20 заранее настроенных публичных страниц с латинскими путями. Один владелец отчёта. Рабочая минимальная версия, не платформа для большого трафика. Есть предел 1000 активных сессий, 5000 идентификаторов событий за 5 минут и 60 событий в минуту на сессию; при превышении часть новых событий отклоняется. Проверка на вашем хостинге обязательна, гарантированная пропускная способность не заявлена.

Нужны PHP 8.2 или новее, HTTPS, возможность создавать папку вне публичной директории и записывать в неё из PHP. База данных, npm и сборка для установки не нужны. Рекомендуется актуальная поддерживаемая версия PHP.

Конструктор без PHP, Tilda, Webflow и GitHub Pages не выполняют эти PHP-файлы. Комплект нельзя внедрить на них только вставкой JavaScript. Потребуется другая серверная архитектура; эта версия допускает только сбор на том же домене. Вебвизор, география, рекламные расходы, бот-фильтрация уровня Метрики и интеграция оптимизации Директа не включены. Старую историю автоматически не восстановит. Метрику можно оставить рядом.

## Установка

### 1. Подготовьте хостинг

В панели хостинга найдите корень сайта. Часто он называется public_html, www или htdocs. Для этой версии папка site-stats должна лежать непосредственно внутри публичной папки сайта. Проверьте HTTPS и исполнение PHP. Если сервер показывает PHP-код как текст, удалите загруженные файлы и настройте обработчик PHP до продолжения.

### 2. Задайте ключ установки

В public/site-stats/install-key.php замените единственную строку REPLACE_WITH_YOUR_OWN_RANDOM_KEY_32_CHARS на свой случайный ключ длиной не меньше 32 символов. Создайте его в менеджере паролей. Это не пароль отчёта. Не используйте этот же ключ где-либо ещё и не отправляйте его в чат нейросети. Установка с исходной строкой запрещена.

### 3. Загрузите папку

Загрузите **содержимое public**, а не весь архив, в корень сайта. Получится:

```
папка_домена/
├── public_html/                  ← публичный корень
│   ├── ваши существующие файлы
│   └── site-stats/               ← папка из public
│       ├── index.php
│       ├── install.php
│       └── ...
└── site-stats-private/           ← создаст установка, вне сайта
    ├── config.php                ← настройки и хеш пароля
    ├── counts.json               ← появится при первом событии/открытии отчёта
    └── store.lock
```

Если PHP не может создать папку рядом с public_html, создайте site-stats-private самостоятельно в этой позиции и дайте пользователю PHP право записи. Права по умолчанию: 0700 на папку и 0600 на файлы. Не ставьте 0777 и не переносите хранилище внутрь сайта. При open_basedir попросите поддержку разрешить PHP доступ именно к этой папке.

### 4. Откройте установку

Откройте https://ваш-домен/site-stats/install.php. Используйте тот вариант домена, на котором реально работает сайт: с www или без него. Введите ключ, название, новый случайный пароль отчёта длиной минимум 14 символов и список реальных публичных страниц. Пример строки: /services | Услуги. Главная: / | Главная. Удалите несуществующие примеры. До 20 строк; без параметров URL, кириллических путей, личных кабинетов и путей с именами/идентификаторами клиентов.

После сохранения браузер попросит войти. Логин **admin**, пароль тот, который вы задали. Отчёт: https://ваш-домен/site-stats/index.php. Не передавайте пароль в URL. Если пароль не принимается на CGI-хостинге, поддержка должна разрешить передачу Authorization в PHP; fallback HTTP_AUTHORIZATION уже реализован.

### 5. Вставьте счётчик и подключите согласие

Добавьте перед закрывающим тегом head в общий шаблон всех нужных страниц:

```html
<script defer src="/site-stats/tracker.php"></script>
```

Если на сайте CSP, она должна разрешать свои скрипты и свои POST-запросы: script-src 'self' и connect-src 'self' в соответствующих правилах. Не удаляйте остальные ограничения сайта.

Если уже есть баннер согласия на аналитику, подключите эти вызовы к его разрешению/отказу. Вызывать после загрузки скрипта:

```js
window.SiteStats?.consent(true);  // разрешение аналитики
window.SiteStats?.consent(false); // отказ или отзыв
```

При существующем баннере синхронизируйте его состояние со SiteStats при каждой загрузке страницы. Вызов optional chaining до загрузки скрипта ничего не сделает. Безопасный момент для обычного defer-скрипта: DOMContentLoaded.

Если баннера нет, возьмите examples/consent.html, добавьте его разметку и код в общий шаблон. В нём уже есть скрипт tracker.php, поэтому второй раз подключать его не нужно. Обязательно адаптируйте текст под фактическую обработку данных и ссылку на вашу политику. Оставьте доступную кнопку «Отключить аналитику» с data-stats-revoke. Пример не является универсальным юридическим согласием.

Счётчик сам запоминает решение в localStorage. До разрешения он не создаёт сессию и не отправляет события collect.php. Загрузка файлов сайта и самого скрипта всё равно видна техническому серверу. После отзыва останавливаются новые события и повторы отправки; уже принятые суммарные данные не стираются. Индивидуального удаления одной сессии из сводок в версии 1.0 нет. Конкретный правовой сценарий надо оценить до использования; нельзя обещать соответствие 152-ФЗ лишь из-за отсутствия cookies.

### 6. Добавьте заявку только после успеха

В обработчике формы после подтверждения сервером успешного приёма:

```js
window.SiteStats?.track('lead');
```

Не на клик по кнопке, не на начало отправки и не после одной валидации. Поля формы передавать не нужно. Повторный вызов означает повторную заявку, автоматического сопоставления с CRM нет. Для обычной ссылки телефон/почта/Telegram/WhatsApp события считаются автоматически. Для собственной кнопки:

```html
<button type="button" data-stats-event="cta">Запросить расчёт</button>
```

Для ссылки или более сложного компонента можно явно вызвать SiteStats.track('cta') в своём обработчике. Не сочетайте ручной вызов с автоматическим событием для того же действия. Не отправляйте персональные параметры: API принимает только имя события.

### 7. Проверьте и закройте установку

1. Откройте настроенную страницу в приватном окне с ?utm_source=telegram. До разрешения не должно быть запросов collect.php в Network.
2. Разрешите аналитику. Должен появиться POST collect.php с ответом 204.
3. Обновите отчёт. Появятся сессия, просмотр и источник Telegram.
4. Перейдите на вторую настроенную страницу. Должен появиться ещё один просмотр. Клик по Telegram/телефону даст действие.
5. Отзовите согласие. Новые действия не должны отправляться. Уже отправленный запрос нельзя отменить задним числом.
6. Откройте отчёт в другом приватном окне: требуется пароль. Попытка открыть https://ваш-домен/site-stats-private/counts.json не должна отдавать данные. Если отдаёт, немедленно уберите установку из публичного доступа и исправьте расположение хранилища.
7. Удалите **только install.php и install-key.php** этой установки с сервера. Остальные файлы нужны для работы. Убедитесь, что эти два адреса теперь отвечают 404.

## Что хранится

Суточные суммы за последние 90 календарных дней в выбранном часовом поясе: просмотры, сессии, события, категории источников, разрешённые идентификаторы страниц и категории устройств. Техническое состояние активных сессий: случайный ID вкладки, время последнего события, категория источника/устройства и счётчик частоты. Оно удаляется после 30 минут без событий при следующем запросе. ID событий нужны 5 минут для защиты от дублей повторной отправки. Очистка выполняется при поступлении события или открытии отчёта. Если установку перестали использовать, старые файлы остаются до следующего запроса или ручного удаления владельцем.

Не записываются IP, полный адрес, произвольные UTM, поля форм, имя посетителя, сырой User-Agent и журнал маршрутов отдельных людей. К серверу по сети всё равно приходит IP; веб-сервер и хостинг могут вести отдельные access/error logs. Состав и хранение этих логов настраивает владелец хостинга. Приватная конфигурация хранит хеш пароля, название, домен, часовой пояс и разрешённые страницы. Отсутствие имен/IP в counts.json само по себе не определяет правовой статус всего потока данных.

## Обслуживание и ограничения

- Резервная копия: скопируйте site-stats-private вне публичного сайта. Для согласованной копии сначала приостановите новые события или используйте снимок хостинга. Не храните архив с конфигом в public_html. Копия содержит статистику и хеш пароля.
- Обновление: замените файлы public/site-stats, сохранив приватные config.php и counts.json. Не загружайте заново установщик без необходимости. При изменении структуры данных нужна проверка совместимости.
- Добавить страницу: отредактируйте массив pages в приватном config.php, сохраняя уже существующие ключи p0, p1. Новому пути новый ключ. Максимум 20 страниц; соблюдайте ту же валидацию, что в установщике. После этого перезагрузите страницу, чтобы получить настройки счётчика.
- Сменить пароль: создайте локально хеш через PHP `password_hash('новый пароль', PASSWORD_DEFAULT)` и замените только password_hash в приватном config.php. Не передавайте пароль нейросети. Если доступа к PHP-консоли нет, попросите поддержку хостинга помочь сменить хеш без публикации пароля или файла-генератора. Не удаляйте counts.json ради сброса пароля.
- Выключить сбор: уберите tracker.php из шаблона сайта. Для полной остановки обработчика также закройте collect.php на сервере. Решение о удалении/хранении данных принимает владелец.
- HTTP 403: другой вариант домена, неверный Origin или сервер не передал признак HTTPS. За доверенным reverse proxy настройте HTTPS на уровне веб-сервера. Не доверяйте произвольному X-Forwarded-Proto из браузера.
- HTTP 400: неразрешённая страница/событие/поле. HTTP 429: сработал лимит. HTTP 503: проверьте папку, права, config.php, свободное место и целостность counts.json. Повреждённое хранилище не перезаписывается пустым автоматически.
- Цифры будут отличаться от Метрики из-за согласия, блокировщиков, способа подсчёта сессий, фильтрации и настроек страниц. Браузер может заблокировать любой счётчик.
- Origin и лимиты уменьшают случайный/чужой сбор, но не защищают статистику от намеренно подделанных запросов. До размещения в открытом интернете используйте ограничения частоты запросов collect.php и попыток входа на уровне хостинга. Нагрузочное испытание на конкретном сервере не проводилось.
- Нельзя гарантировать доставку события при мгновенном закрытии вкладки или сетевом сбое. Повторы возможны только пока страница открыта; очередь событий на диск браузера не создаётся.

## Для разработчика

Исходники без внешних зависимостей для работы. Для локальных тестов нужна Node 24.18+ и npm 11.16+, PHP WASM устанавливается только для проверки. `npm install`, затем `npm test`. В реальном PHP-хостинге эти Node-пакеты не нужны. Просмотр демо не выполняет PHP и не собирает аналитику. Проверки установки, Origin, приватности, авторизации и формы отчёта находятся в tests. Подробности проверки сборки в VERIFY.md.

Основа: собственный сборщик TRIKE, адаптированный для независимой установки. В комплект не включены реальные данные, доступы или конфигурация TRIKE.
